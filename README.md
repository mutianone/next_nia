# 境智 · 出入境业务智能辅助平台

当前版本为 **0.2.0，第二阶段：人员事实档案与法规知识库**。系统支持 macOS 和 Linux，提供本机可运行的前后端、五套主题及明暗模式、响应式布局、环境与 AI 配置，以及本地资料管理和法规检索。

## 当前能力

| 模块 | 已实现范围 |
| --- | --- |
| 工作台 | 读取当前数据库中的人员、停留记录与知识库统计；不再展示虚构预警 |
| 人员事实档案 | 新增、编辑、搜索、分页、人工核验状态、可逆归档；证件号码归一化与去重 |
| 停留记录 | 入境、准许停留截止、离境等事实录入与日期关系校验；未知期限保留为空 |
| 人员 CSV | 模板下载、导入预检、全有全无导入、按当前筛选导出、导出公式注入防护 |
| 法规知识库 | 本地 TXT、Markdown、可提取文字的 PDF、DOCX 导入；原件保存、条款分段、版本、审核发布与生效区间管理 |
| 法规检索 | 本地 BM25 与字词精确匹配融合检索，按查询日期筛选已发布且有效的资料，展示来源与版本 |
| 法规问答 | 接入硅基流动或 DeepSeek；显式确认后发送本次问题与获准外发的公开法规片段，校验返回的引用标识 |
| 外观与设置 | 五套主题、白天/黑夜模式、移动布局、系统信息、SQLite/PostgreSQL 环境与 AI 服务商设置 |
| 后续模块 | 期限预警、正式文书、录音转写、智能笔录、事实画像、旧数据迁移仍未启动 |

**当前没有登录、身份认证和用户权限体系，默认只供本机验收。** 手机安装包未启动；响应式网页不等于 Android 或 HarmonyOS 安装包。

本地人员管理、知识导入和默认检索不需要云端 API。问答属于可选联网操作；尚未使用真实在线模型完成端到端验证。引用标识校验只证明引用来自本次提供的材料，不能保证结论在语义或法律上正确。

## 本机启动

准备 Node.js **20.19+ 的 20.x 版本，或 22.12 及以上版本**（含 npm；不支持 21.x 和 22.0–22.11），以及 Python **3.11 或更高版本**。Node.js 要求与 `package.json` 的 `^20.19.0 || >=22.12.0` 一致。

在项目目录执行：

```bash
bash scripts/setup.sh
bash scripts/dev.sh
```

首次安装或从第一阶段升级时重新运行 `setup.sh`，安装本阶段新增的文件解析依赖。该脚本需要可用的软件包源；前端运行不加载在线字体、CDN 脚本或远程图片。

启动后访问 [本地预览](http://127.0.0.1:5173)，后端健康接口为 [API 健康检查](http://127.0.0.1:8000/api/health)。前端通过 Vite 将 `/api` 请求代理到 `127.0.0.1:8000`。

8000 或 5173 端口被占用时，脚本会退出并说明原因，不结束已有进程。按 `Ctrl+C` 仅停止本次脚本启动的服务。后端默认不开启自动重载；修改后端代码或运行环境后，停止脚本再启动。

## 使用顺序

1. 在人员档案中手工录入资料，或先下载 CSV 模板、填写资料来源并预检，再确认导入。示例行是虚构内容，使用前替换。
2. 在知识库中导入法规原件，核对解析文本、来源、版本与生效日期后发布。导入不会自动认定资料具有法律效力。
3. 先使用本地检索查看条款及原件。仅在需要 AI 辅助解释时启用服务商，并把适合外发的公开法规单独标记为允许外发。
4. 发起问答前明确确认本次外发。系统不会自动加入人员档案或停留记录；问题框本身会发送给服务商，不应填写人员身份、笔录或其他非公开资料。

扫描版 PDF 需要先用另外部署的**本地 OCR 工具**处理；本阶段不自带 OCR。普通 DOCX 和文字 PDF 的解析结果仍需人工核对，复杂表格、页眉页脚与条款分页可能影响分段。

详细操作、数据字段和边界见 [第二阶段说明](docs/phase-2.md)。

## 环境与数据

默认数据存放于 `backend/data/`：`settings.json` 保存服务端配置，`test.sqlite3` 保存测试环境业务表和审计表。知识库原件及解析文本保存在当前数据库中。

需要指定其他数据目录时，在启动前设置绝对路径：

```bash
export NEXT_NIA_DATA_DIR="/absolute/path/to/next-nia-data"
bash scripts/dev.sh
```

`.env.example` 仅说明可用环境变量；**后端与启动脚本不会自动加载 `.env` 文件**。更换数据目录会使用另一套独立配置和数据，不搬迁原目录。

测试模式使用 SQLite，正式模式使用已配置的 PostgreSQL。正式环境保存前验证连接；**环境切换重启生效，不自动迁移、合并或复制数据库**。启动时创建本应用尚不存在的表，保留既有数据；当前没有通用数据库结构迁移工具。PostgreSQL 尚未经过真实服务集成验证。

“正式模式”表示数据库配置模式，不表示已经完成多人生产部署。数据库故障不会自动回退测试库或补入虚构业务数据。

## AI、可选检索与密钥

服务商地址固定为硅基流动或 DeepSeek。连接测试只访问模型列表接口；问答另行检查 AI 开关、默认服务商、凭据、资料外发标记及本次确认。模型列表检查通过不代表问答质量或所选模型的结构化输出能力已经验证。

默认检索为本地词法检索，不要求向量模型。可选的 SentenceTransformer 本地语义检索通过 `NEXT_NIA_EMBEDDING_MODEL_DIR` 配置，需另装可选依赖并提前准备完整模型目录。**默认安装没有这些重型依赖或模型，也没有完成本地语义模型运行验收；程序不会自动下载模型。** 详见 [部署说明](docs/deployment.md)。

配置读取接口只返回密钥是否已配置，不返回原文；留空保留已存密钥，清除需独立操作。`settings.json` 权限为 `0600`，但其中的 API Key 和数据库密码仍是**本地明文存储**，未实现密钥加密或密钥管理服务。配置、数据库、虚拟环境和依赖目录均忽略提交。

## 项目结构与检查

```text
src/                       React + TypeScript 前端
backend/app/               FastAPI、人员、知识库、检索与受限问答服务
backend/tests/             后端功能与数据边界测试
backend/requirements.txt    默认 Python 依赖
backend/requirements-semantic.txt  可选本地语义检索依赖
backend/.venv/             本机虚拟环境（不提交）
backend/data/              默认运行数据（不提交）
scripts/                   macOS/Linux 环境检查和启动脚本
docs/phase-2.md             第二阶段功能与使用说明
```

```bash
npm run typecheck
npm run build
backend/.venv/bin/python -m pytest backend/tests
bash -n scripts/common.sh scripts/setup.sh scripts/dev.sh
```

检查结果以当前实际输出为准。自动测试中的外部服务替身，不等同于真实 PostgreSQL、真实在线模型或可选本地向量模型已验收。`npm run build` 只生成前端静态文件，单独打开 `dist/index.html` 不能运行完整系统。
