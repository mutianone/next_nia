# 第三阶段：结构化 QA 影子回填验收

日期：2026-11-15。分支：`feat/qa-template-shadow-fill-stage3`，基于第二阶段提交 `669fb29`。

本轮新增独立的模板匹配预览。没有切换正式回填，没有改变原 Word 模板、采集方式或 Fun-ASR 服务，没有执行生产迁移或调用真实云端服务。测试使用临时数据库、合成文字和模拟 API。工作区原有未提交修改保留。

## 现有模板结构与数据流

- 三份原模板通过 JSON 定义字段 ID、问题标签、Word 段落与字符范围，原 DOCX 是导出的样式来源。模板配置按修订追加，笔录保存创建时的模板快照。
- 正式链路为可编辑转写片段 → 原有问答候选/模型抽取与校验 → `template_snapshot.values` → 原 Word 字符范围替换。`record_jobs.py`、`records_ai.py` 与连续录音分析仍保留该链路。
- 询问开始/结束年月日时分及地点属于系统字段，不参与新问答匹配。`locked_fields` 中的人工字段禁止接受替换候选。新候选无论来源是规则还是语义建议，均需人工审核。
- 三份原 Word 没有通用的动态自由问答区域。未匹配问答独立保留，不强塞进固定问题。解析器支持定义为 `free_qa` 的字段，但不会为原 Word 新增段落或字段。
- 新链路为已确认 QA 草稿 → 来源校验 → 模板解析 → 字段匹配 → 独立批次/候选 → 人工审核记录。没有向 `record_segments`、正式模板值或原有导出接口写入。

原有三项 `test_original_word_template_filled_and_samples_removed` 失败原因：夹具把模板问题和回答放在一个 `interviewee` 片段里，缺少可确认的民警提问来源，既有校验不接受它。断言在生成文本检查阶段失败，尚未执行 Word 样式验收。本轮没有放宽来源校验使旧测试强行通过，也没有宣称正式链路问题已解决。

## 数据库与迁移

| 表 | 内容 |
| --- | --- |
| `record_fill_batches` | 草稿 ID/修订、模板完整快照及版本、来源摘要、幂等签名、创建人和时间 |
| `record_fill_candidates` | 独立候选、QA Pair ID、原始问答、字段、匹配方式、来源引用、位置和审核修订号 |
| `record_fill_reviews` | 追加的接受/拒绝/人工修改记录、目标字段、有效值、操作人、时间和版本 |

`upgrade(engine)` 对三表逐一使用 `checkfirst=True`，不修改旧表、不迁移或删除旧数据。重复执行在临时库测试通过。部署操作应按现有流程备份、指定正确数据库，再显式执行迁移；本轮未执行生产迁移。

批次签名包含草稿 ID/修订、来源摘要、模板摘要、明确绑定和语义建议。重复请求复用原批次。不同匹配版本独立保存，已审核版本不被重新生成覆盖。审核通过笔录写锁与候选修订检查串行化，旧版本审核返回 409。审计日志只记录操作、笔录标识与登录用户，不记录问答正文。

## API

现有 `/api/records/{id}` 前缀、鉴权及角色权限保持一致。写操作需要 `expected_revision`，审核操作另需 `candidate_revision`。操作人由登录会话决定。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/fill-preview` | 从指定 `draft_id`、`draft_revision` 生成或复用候选批次 |
| GET | `/fill-candidates` | 查询批次与候选，支持 `draft_id`、`batch_id` |
| POST | `/fill-candidates/{candidateId}/review` | `ACCEPTED`、`REJECTED` 或 `MODIFIED`；仅保存影子审核 |
| GET | `/fill-comparison` | 正式字段现值、原问答、影子审核值与来源变化状态 |

预览请求可提供 `bindings: {qa_pair_id: [field_id]}`。空绑定明确保留未匹配。可选 `use_semantic=true` 必须同时明确 `confirmed=true`，并通过现有 AI 外发权限；只调用现有配置的模型。默认完全本地规则匹配。语义请求不发送答案，只发送问题与字段定义，模型返回字段 ID，不允许生成事实。云端调用期间释放数据库锁，返回后重新校验来源和模板。

## 匹配与保护规则

1. 明确绑定优先。
2. 对标签及 `match_rules` 做 Unicode、空白、标点规范化后的精确匹配。保留否认词、数字与语义文字，不用问号判定身份。
3. 匹配已有 `question_aliases`。
4. 可选模型仅提供给定字段 ID 建议，仍是待审核候选。
5. 不确定则保留未匹配，由人工选择字段；唯一的显式自由问答字段可接收原问答。

`allow_shared_source` 必须在所有目标字段上明确允许，才能把同一问答用于多个字段。相同 `exclusive_group` 冲突会阻止接受。一个字段有多个问答时，默认冲突；只有显式 `allow_multiple` 才允许多个候选。审核时需先拒绝冲突项，不能忽略冲突直接接受。原三份模板没有自行启用共享或自由区域；本轮未扩展模板编辑器的这些高级配置控件。

每个候选保留完整答案，不截断、不改写。人工修改另存 `HUMAN` 来源，不冒充识别原文。来源引用保存识别运行、句子、字符范围、说话人/角色、音频及原有时间轴；不存在的精确时间不会补造。来源、角色确认、正文或模板快照变化时，旧预览标记过期，阻止审核。

## 验收与指标

三份原模板各验证两组独立问答：

| 模板 | 字段 ID 匹配 | 答案逐字保留 | 原 Word 导出兼容 | 正式数据未改 |
| --- | --- | --- | --- | --- |
| 外籍新娘 | 通过 | 通过 | 通过 | 通过 |
| 外籍新娘家属 | 通过 | 通过 | 通过 | 通过 |
| 组织他人偷越国（边）境、提供变造护照 | 通过 | 通过 | 通过 | 通过 |

导出测试只对内存模板副本设置值，检查 DOCX 中答案存在，其他 ZIP 资源逐字一致。没有替换生产导出链路；这不是人工打印版式验收，也没有声称测试所有字段的真实语义表现。

固定的 10 条合成字段匹配验收集：三份原模板各两条精确问题、两条别名、两条应保留未匹配的问题。

- 自动建议匹配正确率：**8/8，100%**。
- 自动匹配覆盖率：**8/10，80%**。
- 需人工选择目标字段：**2/10，20%**。
- 需人工审核候选：**10/10，100%**；不存在自动写入正式笔录。
- 答案原文保留：**10/10**。
- 未测量实际人员审核耗时、真实音频识别准确率或真实业务全字段匹配率，不能将上述合成指标外推。

典型粘连对照（合成场景）：原有单长文本风险形式为“你叫什么名字？张某。你住在哪里？我住在依安县某小区。”；影子输入必须是已确认的两组 QA，分别产生姓名与住址两个候选。长回答“我在家里。\n后来有人敲门。”完整保留在第一组，追问“具体几点？”及“八点左右。”单列第二组，并保留追问关联。未知角色、未确认草稿或缺少明确问答关系的内容不能进入此流程。

## 下一阶段与上线边界

**当前不具备直接切换正式回填的条件。** 可以使用影子预览验证字段与来源，但必须先修复正式模板流程的既有失败，用更多真实业务形态的脱敏标注材料比较匹配效果和审核耗时，再设计受控的“已审核候选应用”事务。

下一阶段需要明确：按字段版本接受的原子写入、人工锁定保护、一个字段多个答案的文书呈现、自由问答与三份 Word 的位置约定、系统时间字段和身份元数据的精确格式，以及失败回滚。多字段共享等高级策略已由解析器与服务支持，现有模板编辑器暂未提供新增控件。新的独立问法若未配置别名仍可能未匹配，语义建议质量也尚未通过真实云端评测。
