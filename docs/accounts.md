# 账号与权限

登录页使用警务蓝、雷达扫描、动态网格与盾形图案，手机采用上下布局，系统“减少动态效果”设置下停止动画。不加载外部字体、认证服务或图片资源。

首次启动会在没有任何账号的数据库中创建管理员 `15210451737`，初始密码 `123456`。现有数据库升级时自动建表；后续启动不会重置密码，也不会在所有账号停用时重新植入管理员。当前按用户要求保留初始密码，不强制首次修改，登录页不展示凭据。正式使用前应由管理员自行修改。

账号入口在 **后台配置 → 账号管理**；个人资料、密码、退出入口在右上角头像菜单。手机号是唯一登录标识，不包含短信登录、自助注册或短信找回。姓名必填，部门（100 字以内）和备注（1000 字以内）选填；管理员可在新增/编辑账号中维护，列表展示并支持搜索。用户可修改自己的姓名，在个人信息中查看部门及备注；手机号、部门、备注与角色由管理员统一管理。升级时自动为已有账号补充空白部门和备注，不改变原密码及权限；旧版账号备份可正常恢复。账号不硬删除，停用保留历史业务资料。

## 身份与会话

- PBKDF2-HMAC-SHA256，独立随机盐，600,000 次迭代，数据库不存明文密码。
- 随机不透明会话，数据库只存令牌摘要。HttpOnly / SameSite=Strict Cookie，HTTPS 下附加 Secure，8 小时到期；前端不将凭据放进 localStorage。
- 每次 API 请求检查账号启用状态和当前角色；修改账号、停用、管理员重置密码、本人修改密码会撤销该账号所有会话。退出仅撤销当前会话。
- 5 次账号密码验证失败会锁定该账号 15 分钟；同一连接来源 15 分钟内最多 30 次失败，防止无限枚举不存在的手机号。管理员重置密码可解除锁定。
- 未登录访问业务接口返回 401，越权操作返回 403，前端同步限制导航和操作入口。保留来源校验，阻断跨站写请求。登录过期或被撤销后返回登录页，未保存内容不持久化。
- 至少保留一位启用中的管理员；SQLite 写锁 / PostgreSQL 事务锁串行化账号调整，避免并发禁用最后管理员。
- 登录、账号管理和业务写请求留存操作者 ID 与操作资源，不记录密码、登录令牌或业务正文。业务原有来源记录与版本历史继续保留。

备份包含账号与密码摘要，不包含活跃登录会话、登录尝试计数；恢复不会复活原会话。旧版本无账号表的备份仍可校验并恢复，首次启动创建初始管理员。备份应按业务数据库同等权限保管。

## 验收

后端 `test_auth.py` 覆盖未登录拦截、各角色越权、下载限制、账号停用与重置的会话撤销、最后管理员保护、密码修改与重启持久化、错误次数锁定、跨站请求、备份排除会话。前端 `auth/Auth.test.tsx` 覆盖登录表单、会话失效、无用户时默认拒绝操作、账号创建表单。既有业务测试使用显式登录的管理员 fixture，不绕过生产权限检查。

开发/展示启动脚本仍只监听本机。部署到内网时使用同源 HTTPS 入口，保留原始 Host 与受信任代理的 scheme 配置；不启用任意跨域凭据访问。macOS/Linux 支持范围不变。
