# 第三阶段：期限预警与本地文书

本说明对应 **0.3.0 / stage 3**，在已有人员档案、停留记录和法规知识库上增加期限核查与模板文书。界面继续支持五套主题、明暗模式和移动布局。运行范围为 macOS/Linux 本机验收，无登录和用户权限体系。

本阶段不调用 AI 生成预警结论或填补法律措辞。规则、核查事实、处置历史、模板、文书及导出全部在当前活动数据库和本地服务内处理。不自动导入旧系统真实人员资料，不生成演示预警。

## 期限提醒如何产生

规则使用当前**北京时间日期**，比较已登记的停留事实。签证有效截止日期独立保存，不作为准许停留截止日期。

| 分类 | 生成条件与含义 |
| --- | --- |
| 临近登记期限 | 事实可用，截止日期在未来且进入提前提醒窗口 |
| 登记期限今日届满 | 截止日期为今天，不把当天计为已经逾期 |
| 已超过登记期限 | 已登记截止日期早于今天，提醒核查延期、离境及其他事实；不自动认定非法滞留 |
| 事实待核查 | 期限未知、人员或补充事实未核实、延期待审批、材料/日期矛盾等，需要人工确认 |

“事实待核查”的显示截止日期和剩余天数为空，避免把未确认日期显示为确定倒计时。临近期限且剩余天数进入重点关注窗口，以及今日届满/超过登记期限的提醒，会标记重点关注；它是工作优先级，不是法律风险评分。

存在以下情况时需人工核查：同一人员多条当前未离境记录、未来的离境日期、停留期限早于入境日期、延期申请尚在审批、未核实的延期材料、延期日期与状态不一致等。受理回执日期不会直接替代停留许可。只有已核实、有来源且日期关系有效的批准延期，才以批准后的截止日期作为本次期限依据。

人员已归档、尚未到登记入境日期、已登记且已到实际离境日期，或期限已超出当前提醒窗口时，不再生成当前期限提醒；已有活动提醒会自动关闭。自动关闭不构成法律结论。

每条停留记录保留一条预警及其历史。重复扫描更新同一记录，避免堆积重复提醒。手工关闭后，仅时间倒计时或关注级别变化不会立即重开；关键事实、分类、期限发生变化，或自动关闭后的提醒条件重新出现时，会重新进入待处理并记录原因。

## 工作台操作

1. 在人员档案中登记人员、入境日期、准许停留截止日期和信息来源；资料核对后设置人员核实状态。未知日期保持为空。
2. 点击“补充核查事实”，通过人员搜索选择停留记录。即使没有预警，也可提前录入签证有效期、延期状态、批准截止、回执日期和材料说明。
3. 未核实的材料可以先保存；勾选“已人工核实”时，必须提供来源，已批准延期必须有批准截止日期。核实标记只说明材料核查状态。
4. 保存后运行“立即扫描”，查看本次检查、新建、更新和关闭数量。失败会显示实际错误，不显示成功统计。
5. 使用状态、类别、姓名或档案编号筛选。统计卡展示全库当前待处理与核查中的数量，不受当前列表搜索条件影响。
6. 在详情中查看触发原因、来源、登记期限、独立签证日期和历史；选择开始核查、关闭、重新打开或补充备注。所有人工动作均要求备注。
7. “关联起草文书”携带人员、停留及预警标识进入建稿，不自动填写处理决定或法定文案。

人员停留原始日期仍在“人员档案”中维护；事实补充窗口维护的是延期、回执及核查材料。保存补充事实不会伪装为已经完成一次扫描。

## 扫描规则与运行边界

默认开启自动扫描：提前提醒 **30 天**，重点关注 **7 天**，间隔 **60 分钟**。

- 提前提醒允许 0–365 天；0 表示不提前提醒。
- 重点关注为 0–提前提醒天数。
- 扫描间隔允许 1–10080 分钟。
- 开关控制自动扫描，关闭后仍可手动扫描。
- 自动任务只在后端进程运行时工作，约每 30 秒检查是否到期。下次时间是按规则计算的计划时间，并非秒级执行承诺。
- 后端停机时不扫描，重启后按是否到期补做一次当前扫描，不重放停机期间所有历史时点。
- 手动扫描不接受日期或请求体，始终使用当前北京时间。批次扫描和对应历史在数据库事务内完成。

列表读取最后一次扫描结果。修改事实或规则后，可主动扫描并刷新；上次、下次和失败原因在规则区域显示。没有提醒不意味着系统已证明人员合法停留。

## 模板与标准文案

启动时仅初始化一份**内部核查工作单（非执法决定）**。其 `internal / approved` 状态用于内部整理流程，不代表已批准任何法定文书措辞，也不初始化人员或文书实例。

限期出境相关文书的正式名称、标准措辞、期限填写规则、文号、救济告知和版式仍需业务方提供并确认。系统没有用 AI 或网上片段拼出一份“官方标准通知书”。

模板支持名称、版本、内部/业务类型、来源、正文及复核意见。新模板为草稿；人工批准要求来源、复核意见及明确确认。已批准模板内容只读，可归档；修改需新建版本。归档模板不能新建文书。

正文使用白名单内的 `{{变量名}}` 占位符，变量面板区分人员、停留和人工填写字段。系统不执行模板表达式、脚本或 HTML，不支持任意变量。单份模板最多 50000 字、200 个占位符。

## 文书制作与快照

1. 新建文书，选择模板、未归档人员和对应停留记录；如从预警进入，预填关联标识。服务端校验三者归属一致。
2. 创建时固定模板和人员/停留快照。姓名、证件、国籍和停留日期来自快照，只读；事实说明、人工核定期限、依据、处理意见、单位和经办人等按模板需要人工填写。
3. 编辑中可以保存缺项草稿，预览保留未填变量并列出缺项。人员资料后来变化不会静默改变已有文书快照。
4. 审核前补齐所用变量，核对日期关系、人员快照、事实、依据和正文；填写复核意见并明确确认。源模板必须仍为已批准且内容与创建时快照一致。
5. 文书人工核对后锁定内容，只能归档或复制新草稿；归档文书只读且不能直接导出。复制保留原模板和人员快照，如需更新事实快照应重新从当前档案建稿。

草稿可使用待审核模板做内部整理，但只有符合审核条件的模板才允许文书进入人工核对状态。模板改动导致快照不一致时，按当前模板重新建稿；复制旧稿不能替代更新快照。

模板和文书修改须提交读取时的 `expected_revision`。记录被另一操作更新时返回冲突，当前修改不会覆盖新版本；应重新打开记录，核对后再编辑。

## 导出与保留标识

导出 TXT 和 DOCX 均由本地后端生成，不需要 Office、LibreOffice、在线转换或新增外部 API。DOCX 使用固定的本地 OpenXML 结构，不生成宏或外部资源关系。

- 未补齐模板实际使用的变量时，拒绝审核和导出；不能把缺项空白当作正式结果。
- 草稿保留“草稿·待人工审核，不得作为正式文书使用”。
- 人工核对稿保留“人工核对稿·未签发”。DOCX 正文和页眉均保留对应标识。
- 导出不等于签发、盖章或送达；当前无电子签章、正式签发或送达流程，也不提供 PDF 导出。
- 通用 DOCX 排版不是业务方确认的法定制式版式。目标办公软件中的字体、分页及正式模板排版还需人工核对。
