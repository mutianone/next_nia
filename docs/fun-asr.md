# 阿里云 Fun-ASR 接入

语音转写使用百炼北京地域 Fun-ASR 录音文件识别 HTTP API；对话和模板回填模型独立配置，保持原有设置。未部署本地语音模型。

## 配置

重启后端服务后，以管理员进入“系统设置 → AI → 笔录语音转写”，选择阿里云 Fun-ASR，填写北京地域百炼 API Key 后保存。业务空间 ID 可选，使用其他业务空间时填写对应 ID。现有音频可重新转写验证。

配置保存在 `backend/data/settings.sqlite3`，密钥不通过普通设置查询返回。不要直接编辑数据库或将密钥提交到仓库。没有密钥时，转写会明确提示配置缺失，不会偷偷转用其他服务商。

## 执行流程

沿用现有录音分段保存及后台任务流程。音频规范化后上传阿里云私有临时存储，提交异步识别任务，启用 diarization_enabled，查询结果后保存每个说话人的句子和句级时间戳。模板回填继续经过现有问答整理、依据校验及人工审核。

临时上传使用官方临时文件机制，文件有效期为 48 小时，不表示请求结束即删除；生产环境可进一步接入独立 OSS 留存策略。官方文档：https://help.aliyun.com/zh/model-studio/get-temporary-file-url

已获得任务编号的请求保存在 `backend/data/fun-asr-tasks.sqlite3`，相同音频及凭据重试可继续查询，缓存 36 小时。若提交请求的响应丢失、未取得任务编号，不能保证避免重复提交。后台现有失败重试与原音保留机制继续生效。

说话人编号是单段音频内的音色标识，不代表询问人或被询问人身份，也不能跨音频直接合并为同一个人。当前保留句级时间戳，未单独存储字级时间戳。不保证多人重叠发言、噪音或句尾截断情况下零错误。

## 验证记录

接入与回归：75 项后端测试、6 项前端测试通过，前端生产构建通过。覆盖异步任务继续查询、说话人及时间戳解析、失败响应、结果地址校验、密钥隐藏及保存兼容。

尚未配置真实阿里云凭据，以上为模拟接口及本地回归结果，不代表真实识别质量已验证。后续应使用同一段真实业务形式的虚拟双人问答音频，逐句比较问答边界、句尾完整性及模板回填结果。

## 单麦克风多人笔录

上传后点“转写所选音频”，或在“开始连续录音”前选择预计发言人数。人数包括所有实际发言的人。使用默认设置可沿用原有服务。选择人数时，阿里云使用原生说话人分离并接收人数提示。任务缓存区分人数，连续录音在同一会话的批次和重试中复用该设置。不同识别运行的声音编号各自独立。

使用硅基流动时，可在已安装 FFmpeg 的后端执行 `bash scripts/setup-voice-models.sh`，并在每台录音任务处理机上使用相同模型。脚本安装可选 Python 依赖，下载并验证 ERes2Net 说话人模型和带时间位置的 SenseVoice 模型。默认模型目录为 `backend/data/voice-models`，也可设置 `CRJ_VOICE_MODEL_DIR`。语音服务仍按设置接收音频，本机在原音上计算声音特征并与服务商原文对齐。本机给出的字词时间为估计值。启用本机模型后，阿里云的词时间也可用于和本地声音切换位置交叉核对。

在“文字修订”中可以查看声音编号、回听待核对边界。在“角色与 QA 草稿”的逐句核对中可以拆分原文并分别确认角色和意图。两位民警可映射到同一业务角色。出现声学分歧的发言需要逐句确认，加在声音编号上的角色不能批量确认这些片段。上传音频选择人数后先进入文字核对；服务漏转的词仍需回听原音。
