# 语音转写与多人笔录

录音由配置的语音服务商转写。硅基流动只返回纯文本时，可用本机模型辅助分人；返回带声音编号的原生分段时，保留服务商分段和时间。阿里云百炼北京地域 Fun-ASR、火山豆包录音识别 2.0 支持原生说话人分离。对话和笔录模板回填使用单独配置的文字模型。

## 配置

用 `root` 登录，在“系统设置 → AI 服务 → 笔录语音转写”选择语音服务商。使用阿里云时填写北京地域百炼 API Key，按需填写业务空间 ID。使用 DeepSeek 回填时，在同页配置 DeepSeek 凭据、启用服务并选择它为默认对话服务商。转写成功后若回填提示“凭证或模型权限”错误，应检查对话服务商的 Key、模型权限及文字外发设置，保留已有转写，单独重试回填。以有写权限的业务账号进入“智能笔录”测试。

配置保存在 `backend/data/settings.sqlite3`，密钥不通过普通设置查询返回。不要直接编辑数据库或将密钥提交到仓库。没有密钥时，转写会明确提示配置缺失，不会偷偷转用其他服务商。

## 火山录音识别 2.0 配置与验证

在“系统设置 → AI 服务 → 笔录语音转写”选择“火山引擎 · 豆包录音识别 2.0”。已有硅基流动和阿里云配置保留，切换服务商不会覆盖另一家的密钥；不自动改变当前默认语音服务。

需要填写同一已开通语音项目下的 API Key，以及 TOS 私有桶名称、桶所在地域（例如 `cn-beijing`）、TOS Access Key ID 和 Secret Access Key。语音 Key 与对象存储 AK/SK 是不同的凭据。TOS 凭据需具备该桶 `next-nia-asr/` 前缀下的上传、读取、删除权限；请设置此前缀的 1 天生命周期过期规则。不需要公开桶，也不需要开放本地业务 API 到公网。

火山标准版要求音频 URL。本地规范化的转写副本由后端上传到私有 TOS 对象，使用 24 小时 GET 预签名链接供语音接口读取。终态任务尝试删除对象；网络错误、中断或进程退出可能留下对象，由桶的生命周期兜底清理。限时链接失效本身不等于对象已删除。密钥和预签名链接不写入识别正文、业务日志或任务缓存。

固定调用 `/api/v3/auc/bigmodel/submit` 与 `/query`，资源 ID 为 `volc.seedasr.auc`，鉴权为 `X-Api-Key`。默认开启说话人分离、分句和标点，关闭语义顺滑；默认及 2–5 人采用 `ssd_version=200`，超过 5 人采用会议模式 `300`。预计人数用于选择场景和隔离重试，不作为云端精确人数参数，不能保证编号数等于所选人数。火山原生分人不要求安装本地声学模型，也不会被本机模型覆盖。

任务缓存默认位于 `backend/data/volc-asr-tasks.sqlite3`，可通过 `CRJ_VOLC_ASR_CACHE` 调整，保留 23 小时。相同音频、配置、请求键及人数的重试复用任务；连续录音按批次隔离。等待 180 秒仍未结束时明确提示重试查询。提交响应丢失或缓存落盘失败时，重试可能重复提交；没有宣称严格的只调用一次保证。

每次识别保留原始响应、运行编号、匿名声音、分句及逐字时间。零时长词不扩造时间，标记待核对；缺少声音编号或逐字依据时同样提示回听。分句未覆盖全文、时间异常、静音、凭据或权限错误均不应用不完整结果。角色仍需人工确认，同人的连续短答和补充段分别留存引用。

## 火山 + Qwen3-ASR 双引擎核对

在“系统设置 → AI 服务 → 笔录语音转写”选择“火山 + Qwen3-ASR 双引擎核对”。需同时配置火山/TOS，以及已启用的硅基流动密钥。Qwen 通过硅基流动调用 `Qwen/Qwen3-ASR-1.7B`，不是阿里百炼直连接口；单引擎模型配置不会被覆盖。两家独立计费，保存此设置不会改变对话/回填模型。

上传并转写后，在“文字修订 → 双引擎核对”逐窗口回听，明确选择候选，确认后保存为新识别版本，再核对角色与问答边界、生成模板。不自动推断哪个结果必然正确；相同文本也可能共同识别错误或分错人。缺少时间时按整条录音核对，只有一方返回时明确显示不构成一致。原文与已有人工作品保留，存在其他已应用版本或人工修订时拒绝覆盖。

当前只支持已保存/上传的录音。连续录音的自动回填需选用单引擎；录音过程中切换到双引擎会停止云端批次处理并保留原音，切回单引擎后重试。新投影中若供应商时间超出原音声明时长，保留原始时间在来源证据中，新时间置为未知并标记回听，不裁造词级时间。

12 条真实公共录音已完成双引擎转写、核对选择接口及实际普通模板复测。标注辅助选择后有值 9/12、逐字正确 5/12，不代表自动择优准确率。方法、限制和逐条结果见[双引擎核对实测](dual-asr-comparison-20261118.md)。本轮没有自动切换用户当前默认服务。

双引擎设置另有“自动比对”：默认只用本地规则，可选“规则 + 默认对话模型”或“规则 + DeepSeek”。DeepSeek 选项独立使用已配置的 DeepSeek 对话模型和密钥，不修改默认回填模型。模型模式需启用相应服务及笔录文字外发，音频仍只发送两家 ASR，文字模型收到两份候选文字与分句信息。新转写会自动比较并预选草稿；旧版本可在核对窗口点“自动比对并预选候选”。理由会显示，选择可修改，关键冲突或模型失败保留未选状态；确认前不写正文、不确认角色、不放开回填。

同批已冻结的真实转写用于 DeepSeek 自动比对验证，模型未获得参考标注或上一轮人工选择。结果及失败样例见[自动择选实测](asr-auto-selection-20261118.md)。自动预选提高便利性，不能据此认定比某个单引擎更准确。

## 阿里云任务与识别版本

沿用现有录音分段保存及后台任务流程。音频规范化后上传阿里云私有临时存储，提交异步识别任务，启用 diarization_enabled，查询结果后保存每个说话人的句子和句级时间戳。模板回填继续经过现有问答整理、依据校验及人工审核。

临时上传使用官方临时文件机制，文件有效期为 48 小时，不表示请求结束即删除；生产环境可进一步接入独立 OSS 留存策略。官方文档：https://help.aliyun.com/zh/model-studio/get-temporary-file-url

已获得编号的任务默认缓存在 `backend/data/fun-asr-tasks.sqlite3`，保留 23 小时。音频、凭据、业务空间、请求键和人数提示相同的重试可继续查询。若提交响应丢失且未取得任务编号，重试可能重复提交。

识别版本保存供应商返回的句子、匿名声音编号及可用的句词时间。业务角色单独确认。重新转写已有正文的音频时，可选择新识别版本核对，已有人工正文保留。[识别数据与版本隔离](funasr-stage1.md)

## 单麦克风多人笔录

上传后点“转写所选音频”，或在“开始连续录音”前选择预计发言人数。人数包括所有实际发言的人。使用默认设置可沿用原有服务。选择人数时，阿里云使用原生说话人分离并接收人数提示。任务缓存区分人数，连续录音在同一会话的批次和重试中复用该设置。不同识别运行的声音编号各自独立。

使用硅基流动时，可在已安装 FFmpeg 的后端执行 `bash scripts/setup-voice-models.sh`，并在每台录音任务处理机上使用相同模型。脚本安装可选 Python 依赖，下载并验证 ERes2Net 说话人模型和带时间位置的 SenseVoice 模型。默认模型目录为 `backend/data/voice-models`，也可设置 `CRJ_VOICE_MODEL_DIR`。语音服务仍按设置接收音频，本机在原音上计算声音特征并与服务商原文对齐。本机给出的字词时间为估计值。启用本机模型后，阿里云的词时间也可用于和本地声音切换位置交叉核对。

例如四位民警和一位群众都发言时选 5 人，仅在场旁听的人员不计入。上传音频选择人数后先进入“文字修订”。在“角色与 QA 草稿”中按声音编号回听并确认角色，多位民警可以各自映射为询问人。遇到争议片段时逐句核对，必要时拆句并分别确认角色和意图。服务漏转的词须回听后在人工稿中修订。[多人笔录实现契约](../IMPLEMENTATION.md#多人笔录的说话人与回填依据)

## 可复用的验收方法

### 一位民警与一位群众对坐

支持分人的环境在上传转写、开始连续录音时默认选 2 人，其他人数和“使用语音服务默认设置”仍可手选。双人模式用 FFmpeg 为送转写的副本适度提升轻声部分，保留原音与时间轴。阿里云继续使用供应商的分人结果。硅基流动仅返回全文时，本机保留长句上下文，遇到停顿后的短发言会单独识别，并结合词位置和音色变化定位问答交界。音量、座位远近和第几次发言都不用于认定业务角色。

若短句与云端原文不一致，打开“文字修订”或“角色与 QA 草稿 → 逐句核对与拆分”，点击“回听候选位置”。本机候选保存在该识别版本内，仅供核对。即使两种识别给出相反的肯否，也须由人听原音后修订正文。

在“人工修订 → 角色与 QA 草稿 → 逐句核对与拆分”可核对连续问话。例如民警说“先核对一下时间。你几点到的？我问的是上午。”，群众答“我记不清，可能是十点。”依次把前三句标为民警的“继续发言、独立问题、继续发言”，把最后一句标为被询问人的“回答”。在同一声音、时间连续的情况下，构建草稿后应有一组问答，问题引用前三句，答案只引用第四句。“与上一句的声音相近”是相邻边界的回听提示。两道独立问题应分别标记。

用普通话真人对话 CTS-CN-F2F-2019-11-15-1428 的 1377.15 至 1391.37 秒复测了上述流程。浏览器转写把第一人的三段话归入同一声音编号，第二人的“是的”单独成段。逐句确认后，草稿保留三个问话来源和一个回答来源。开头单字“因”缺少音色依据，仍单列待核对。同一录音的快速问答片段（1362.0 至 1370.7 秒）仍有漏字，末尾的“对”没有进入转写正文。以上材料为日常对话，现场环境的准确率需另测。

2026-11-17 对比使用同一硅基流动模型和本机模型。选取有逐句标注的两场普通话真人对话（CTS-CN-F2F 1428、1434），分别对比原录音与只把回答者区间衰减 12 dB 的副本。下表按去除标点后的回答计数，只有完整原话独立成段才命中，本机候选另计。

| 材料 | 改前 | 改后 |
| --- | --- | --- |
| 5 段对话中的 6 个短答，原始音量 | 1/6 | 3/6 |
| 同 5 段、回答者降低 12 dB | 1/6 | 2/6 |
| 另取 4 段未参与调参的对话、回答者降低 12 dB，核对完整回答 | 3/4 | 3/4 |

弱声版“紧张”从无编号恢复为与提问者不同的声音编号。“不知道”在两种音量下的云端原文都不准确，本机候选保留了完整否定，浏览器核实可回听且模板字段留空。另取的 4 段中，“怎么种植水稻？”一问的识别反而变差。衰减模拟了音量差，实际询问室的距离、混响和设备处理仍需用现场录音复测。

### 多人回归

普通模板补充回答的回归样本可用 Magic Data 的 CTS-CN-F2F-2019-11-15-1447。选取“那你们学校有什么专业呢”一问，确认两段回答属于同一人，在普通模板生成后重新读取字段、候选和两条来源引用。原音和回答者降低 12 dB 的版本均应保留第二段“还有信息。”。本次实测中第一段的“公路系”被转写为“公务系”，核对回答完整性时应同时保留并记录这处识别误差。[语料发布页](https://www.modelscope.cn/datasets/MagicData/A_CHINESE_CONVERSATIONAL_SPEECH_CORPUS/summary)

1. 准备有权用于所选服务商测试的录音，并在识别前逐句标注发言人、原话和起止时间。至少用一段多警轮流追问和一段有抢话或重叠的录音，标出“是的”“我确定”“不知道”等短答及其对应问题。单独保留合成样例和现场录音的结果。
2. 用业务账号上传录音，按实际发言总人数转写。在“文字修订”逐句回听，对照同一个人前后是否串号、不同民警是否误并、切换处是否漏字。记录争议片段是否给出回听位置。再次转写同一音频，检查新版本可核对、旧人工稿仍在。修改连续录音链路时，用同一组发言跨批次重测人数提示和短答归属。
3. 在“角色与 QA 草稿”确认角色和问答边界后生成模板。检查相邻两个短答是否各归其问、回答引用能否定位到原文、否定和限定词是否完整。记录复核前误填、漏转、待核对数量，以及复核后的字段值。四位及以上实际发言人应单列结果。可按[第五阶段离线评测](qa-stage5-validation.md#离线端到端评测)保存逐句和字段对照。

## 以后更换采集设备时

按实际发言席位配近讲指向性麦克风，每席独立输入、独立录轨。例如五位民警加一位群众需要六路独立输入。若要求民警轮流发言，可在民警席使用带发言申请、限制同时开麦数的会议系统，群众席保留独立收音。若要保留同时说出的两句话，应分别录下两席的音轨。

当前浏览器连续录音会混成单声道，后端对非 MP3 的转写转换也输出单声道。接入分轨设备时，要验证设备能向电脑输出各席独立声道，并让采集或导入、存储、转写和回听全程保留声道与席位映射。验收时安排两席同时说不同内容，检查能否分别回放并定位到各自的模板依据。

### 双引擎上传录音的模板预填

录音首次转写后，系统在两个引擎的原文中分别定位模板问题和完整回答。问题或配置的别名唯一命中、来源片段一致、至少一方有问答换人依据且回答文字一致时，系统将回答和补充陈述一起写入空白问答字段，供模板预览。其余字段独立判断。已应用的旧版上传录音可以在“双引擎核对”点击“将一致回答预填到模板”，复用本地识别结果。已有值和受保护字段保留。正式生成和全文锁定沿用原有核对流程。
