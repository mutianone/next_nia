# 连续录音、分段转写与统一回填

## 使用方式

在智能笔录的原始音频页勾选云端处理说明。使用多人分人功能时，先选“预计发言人数”，再点击“开始连续录音”。录音约每5秒保存一次，后台约每45～60秒整理一个转写段，优先选择片尾静音的保存边界。采集不靠反复停止麦克风切段。结束时点击“结束录音并生成笔录”，等待尾段保存与处理完成，再核对成文。人数提示随会话保留，各批次内的声音编号独立。配置和回听步骤见[语音转写与多人笔录](fun-asr.md)。

页面显示采集、后端保存、已有转写和待上传进度。需要保持浏览器页面和设备唤醒。关闭页面、休眠或麦克风故障会中断采集；已保存音频与服务器任务不会因此丢弃。刷新后可选择处理已保存部分，结果明确标记不完整。

## 可靠性和处理规则

- AudioWorklet 将输入真实重采样为16kHz单声道PCM，每个保存分片独立可恢复。分片写入IndexedDB后上传，核对服务器序号和SHA256确认后才删除缓存。
- 服务端按会话和序号幂等保存；同序号不同内容拒绝覆盖。缺失序号阻止正常结束。不完整生成需要用户明确确认。
- 转写优先于增量提取，两个工作线程领取带租约的持久化任务。相邻段按序提取，携带前一段原文处理跨段问答。相同回答去重，真实不同陈述保留并提示核对，不用后完成的请求覆盖先前事实。
- 短段优先一次提取；标准明确问答走原文规则。较大模型输出失败时自动拆为小组，成功检查点不重做。
- 最终合并依据全部成功段和可复用的旧分析，不截断长录音到30000字。总正文仍受100000字保护；超过时保留结果并暂停发布。最终自动校核为来源、顺序、版本和不同陈述检查，不代表语义事实已人工确认。
- 已人工保护的模板字段不被覆盖。补录复用成功的旧转写和当前有效分析；若原文已人工改动，应先重新生成，再开始补录。
- 失败任务有上限的退避重试；配置错误不反复请求。成功转写、成功提取组持久保存。人工跳过失败段须确认，原音保留，正文和Word/PDF导出带不完整标识。
- 浏览器写队列约8MiB、待上传缓存约100MiB、低存储空间触发停止保护；后端磁盘余量低于64MiB拒绝新分片。笔录原音逻辑容量上限500MiB。缓存失败的当前分片暂留内存供下载或重试，不应关闭页面。
- 服务端保留PCM分片和最终WAV，磁盘实际占用会高于逻辑音频容量。部署应预留至少双份音频空间及数据库/备份余量。
- 删除已完成的某段音频，会清除其源PCM与对应转写，清除混合生成候选和历史成文；其他音频保留。

## 架构与部署

新增表：record_captures、record_capture_chunks、record_capture_batches。现有笔录、音频、转写、候选审核及版本表继续复用。首次启动自动创建新表，不修改旧记录。上线前备份数据库。

默认由后端启动两个后台工作线程，网页请求不等待云端处理完成。需要独立进程时：

```bash
# Web进程禁用内嵌录音worker
CRJ_CAPTURE_EMBEDDED=0 bash scripts/dev.sh

# 在另一个终端，从Crj目录启动独立worker
backend/.venv/bin/python -m backend.app.capture_worker
```

两进程须使用相同CRJ_DATA_DIR/数据库和配置。生产使用进程管理器维护worker。租约有效期5分钟，单个云端调用有超时；异常退出后过期任务可重新领取。可能重复外部请求，但旧租约结果不能重复应用。API服务和worker可重启，成功检查点保留。FFmpeg 用于音频规范化。启用本机辅助分人时，API 服务和处理录音的 worker 均需能读取相同的模型文件。

录音授权在创建会话时明确记录；每次任务执行仍检查当前外发权限。原始音频与内容不写入应用日志。数据库保存模板快照、输入摘要、处理状态和模型标识。

## 验证范围

自动化覆盖：超过五分钟的采样连续性、六分钟PCM批处理、顺序合并、重复上传、同序号冲突、账号隔离、缺片、磁盘不足、租约抢占、成功结果复用、跳过失败段、音频关联删除和人工字段保护。

浏览器虚拟麦克风覆盖：真实AudioWorklet采集、录音中转写、断网缓存及补传、结束后回填、刷新恢复、部分录音标识。浏览器验收使用隔离数据库与模拟云端响应，不代表真实云端识别准确率或延迟已经达标。需用现场麦克风、实际模型和长音频继续测量结束后的等待时间。
