# 火山录音识别 2.0：十二条真人对话对照

## 结论

火山长回答分人有进步，但短答边界仍有明显问题；当前不建议把它直接作为无需复核的替代方案。

火山 12/12 请求成功，总测得转写耗时 42.33 秒（顺序调用，非并发吞吐或成本指标）。Qwen 回填使用规则优化后的基线。5 条短答虽然都在全文中，却全部与问话粘连，未作为独立回答回填。

## 重点观察

- **01**：问答合成同一段：你没看过吗？我看过啊。
- **03**：双人分开，3.2 秒停顿后的补充与前段回答保留同号；两段完整回填。
- **06**：“肯定不能啊”仍在全文中，但并入问话；“赎金”误转“蜀军”。
- **07**：同人两段补充完整回填，但仍有“你你”和漏“还”等文字误差。
- **09**：末尾“对”并入问话；结束时间 13750 ms 超出原 WAV 的 13720 ms，角色保存被拦截。未放宽校验或修改时间。
- **10**：较长回答分人稳定，多段内容完整保留到模板；仍有漏字。
- **11**：试探性回答连同问号保留，不改写为肯定陈述。
- **12**：说话人稳定，但回答开头复述问题，现有混问校验拦截；不可只保留后半段。

## 方法与限制

同一批 Magic Data 1452、1458、1461、1463 四场真人会话，12 个片段、8 位发言人、249.642 秒。原 WAV 哈希逐一匹配冻结清单。两组均经项目双人电平调整并转成 16 kHz 单声道 MP3。火山调用 volc.seedasr.auc，ssd_version=200，关闭语义顺滑；Qwen 使用此前冻结转写与最新回填优化后的结果，不重复调用 ASR。

模板使用真实 FastAPI 路由、临时 SQLite 库和真实 Qwen/Qwen3-8B 文字服务；上传原音、导入 ASR 版本、按参考标注确认已有分段的角色，再生成单题普通模板，重新读取字段、候选、正文及引用。混合问答的整段保持未知，不人工拆句补救，不改原文、编号或时间。这里含人工角色确认，不能视为全自动效果，也不代表所有正式 Word 模板。

CER 忽略标点、空白和大小写，保留口语重复，沿用原参考标注中的口语与文字误差，不对数字做额外归一化。火山仅比 Qwen 少 3 个编辑错误，不足以证明普遍更强。整轮分人稳定率不是 DER；短答文字出现不等于独立分人成功。公开日常对话不能代替询问室现场录音，尤其短截取片段可能缺少分人上下文。

“还有信息”来自另一批素材，不在本次 12 条中，本报告不宣称复测了该句。

当前用户选择火山，评测没有自动修改配置。建议先保留两家切换；短问短答回填优先保留 Qwen 基线，火山下一步用完整连续对话与实际询问室录音验证短答。
