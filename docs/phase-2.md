# 第二阶段：人员事实档案与法规知识库

第二阶段把人员、停留事实与法规材料保存在当前本地数据库，并提供可追溯的检索和受限法规问答。默认不导入旧系统个人资料，也不自动灌入示例人员、法规或预警。

## 人员档案

人员档案必填姓名、国籍、证件号码和资料来源。可补充英文姓名、性别、出生日期、证件类型及有效期、联系方式、地址、来华事由和备注。

系统自动生成 UUID 和 `NIA-…` 编号。证件号码去除空白并转为大写，与证件类型组合校验唯一性；已归档档案也参与去重。已有档案通过编辑更新，不重复新建。默认核验状态为“待核验”，人工核对后可改为“已核验”。

归档是可逆操作，不删除人员或其停留记录。列表默认显示未归档档案，可切换已归档；支持按编号、姓名、英文姓名、国籍或证件号码搜索和分页。统计显示全库总人数、未归档已核验/待核验人数和归档人数。

每条停留记录包含入境日期、可选的准许停留截止日期和离境日期、许可类型/号码、事由、来源及备注。入境日期和来源必填；截止日期或离境日期不能早于入境日期，入境日期不能早于已知出生日期。

准许停留截止日期未知时保持为空。离境日期晚于登记的截止日期仍可作为事实保存，系统不会据此自动作出违法认定。期限预警、延期或受理回执规则属于第三阶段，当前未实现。

## CSV 导入与导出

1. 下载模板，替换其中明确标记为虚构的示例行。模板下载不会写入数据库。
2. 使用 UTF-8 CSV，保留英文表头。必需列为 `name`、`nationality`、`document_number`、`source`。
3. 先预检，查看归一化后的有效行及带行号的错误。
4. 修正所有问题后再导入。提交时重新验证，预检通过不保证提交时没有新的重复资料。

一次最多 500 条数据行、文件内容最多 1 MiB。表头错误、必填缺失、无效日期、文件内重复或与现有档案重复都会阻止整批写入。导入采用单个事务；人员写入与审计失败时一起回滚，不保留半批资料。

日期使用 `YYYY-MM-DD`，可选日期留空。枚举值为：

| 字段 | 允许值 |
| --- | --- |
| `gender` | `unknown`、`male`、`female` |
| `document_type` | `passport`、`other` |
| `verification` | `pending`、`verified` |

`id`、`code`、`created_at`、`updated_at`、`archived` 由服务端管理，不作为导入字段。导出包含可编辑业务字段，覆盖当前搜索与归档筛选下的全部记录，不仅是当前分页。

CSV 下载带 UTF-8 BOM；可能被电子表格解释为公式、或原文以单引号开头的单元格会前置一个单引号。人员导出文件额外包含固定为 `safe-v1` 的 `__nia_csv_format` 列；重新导入时，系统校验编码格式后只移除这一层安全前缀，保留原始电话中的 `+`、原始公式前缀和原始单引号。模板不包含该标记，普通无标记 CSV 中的单引号始终作为原文保存。格式标记无效或安全编码被改写会阻止整批导入；请重新导出，手动整理资料则使用模板填写原始文本。导出文件在电子表格中编辑后仍需预检，不能保证第三方软件保留原始 CSV 编码。

## 法规文件与版本

支持本地 TXT、Markdown、可提取文字的 PDF 和 DOCX；单文件上限 10 MiB。导入记录包括标题、版本、发布机关、文号、分类、来源、法规系列标识及发布日期/生效日期/失效日期。

导入后的状态是“待审核”，默认不允许外发。系统保存原件、解析文本和分段关联；可以查看分段并下载原件。上传后的人工核对不能省略：文本提取、条款划分和页码对应可能受原文件布局影响。

扫描 PDF 先用另行部署的本地 OCR 工具转成文字 PDF 或文本；本阶段不含 OCR，也不会调用在线转换接口。旧 `.doc` 文件不属于当前 DOCX 支持范围。

发布前需填入已核实的来源与生效日期。版本在同一法规系列中唯一；同一系列的已发布版本不允许生效区间重叠。生效、失效日期均按当天包含计算，例如上一版本截至某年 12 月 31 日，新版从下一年 1 月 1 日生效。

更新法规时导入新版本并核对日期，保留旧版本原件和来源。历史检索需要旧版本仍以正确的有限生效区间保持发布状态；归档的版本不参与检索。没有登记失效日期不等于系统已经确认该法规持续有效，维护人员仍需核实。

“审核发布”目前是本机操作状态，没有实名审核人、双人复核或审批工作流。来源地址作为资料元信息保存，不会自动访问外部法规网站核实内容。

## 本地检索

默认采用本地 BM25 与字词精确匹配融合排序。检索按所选日期，只匹配已发布且处于登记生效区间的版本；草稿、归档及在该日期尚未生效或已经失效的版本不参与。

结果展示材料标题、版本、条款或段落、原文、来源与可用的 PDF 页码。未检索到足够依据时返回空结果，不自行补造法条。日期默认按北京时间计算。

可选 SentenceTransformer 语义检索使用 `NEXT_NIA_EMBEDDING_MODEL_DIR` 指向完整的本地模型目录；程序不自动下载。默认未安装可选重型依赖和模型，当前未完成该路径的真实模型验收。没有可用模型时明确显示词法模式，不把降级结果称为已启用向量检索。安装和运行边界见 [部署说明](deployment.md)。

当前没有持久化向量数据库、GraphRAG、LoRA 微调、自动抓取法规或全量法规准确率验证。

## 受限法规问答

问答使用系统设置中的硅基流动或 DeepSeek 默认服务商。调用前需要：

- AI 总开关和默认服务商启用，且配置有效凭据与可用模型。
- 资料经人工发布、在指定日期有效，并被单独标记 `allow_external=true`。
- 操作者明确确认本次问题与检索片段可以发送到选定服务商。

只应把公开且适合外发的法规标记为允许外发。该标记不会自动判断文件是否公开，也没有自动识别人名、证件号等敏感信息的能力。问题文本会外发，不能把人员身份、笔录或非公开案件内容填入问答框。

系统不会自动关联或发送人员档案、停留记录、原始文件、其他未获准的文档或数据库配置。上传材料中的指令作为被分析的内容，不作为程序指令执行。

服务端要求模型返回结构化结论及来源标识，拒绝不存在的引用标识，再生成界面引用编号。**校验标识存在，不等于证明句子受到该条款支持，也不保证法规有效性、适用性或法律结论正确。** 最终仍需人工阅读原文、核实版本与适用条件。

没有相关可外发依据时，不调用模型并提示材料不足。凭据错误、超时、模型响应格式异常等会明确返回失败，不替换为虚构回答。当前未使用真实在线模型验证问答效果、耗时或费用；自动测试中的模拟响应不代表真实服务已联通。

## 工作台、审计与边界

工作台读取当前数据库的人员、停留记录和知识库统计。测试模式也使用实际录入的数据，不再显示第一阶段的虚构预警。系统尚未实现预警扫描、处罚建议自动决定或文书正式出具。

人员与停留记录的每次写入和审计在同一事务内完成，审计只保存记录标识或数量，不写入姓名、证件号码、来源文本、备注或密钥。无登录意味着目前无法把操作可靠地归属到具体实名用户。

SQLite 与 PostgreSQL 配置模式沿用第一阶段；变更后重启生效，不自动搬迁数据。PostgreSQL 仍需真实环境集成验证。当前只作为本机验收版本，不直接开放为多人业务系统。

第三阶段期限预警与文书、第四阶段录音及笔录、第五阶段事实画像与完整迁移交付均未启动。正式文书的标准名称和固定文案继续等待业务方审定样本。
