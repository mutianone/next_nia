# 分阶段交付与验收范围

各阶段独立开发和验收。阶段一的导航入口用于展示整体结构，未完成模块会明确显示规划状态；演示统计不应作为业务结果使用。

## 第一阶段：基础框架与配置

交付 React + TypeScript + Vite 前端、FastAPI 后端、总览工作台、五套主题的明暗模式、移动布局及系统设置。

本阶段的数据库用于建立运行配置和基础持久化能力。测试环境使用 SQLite；正式模式使用 PostgreSQL。保存环境设置时检查连接，重启后启用目标环境；不做自动数据迁移。正式模式工作台不灌入测试演示数据。

AI 仅实现硅基流动/DeepSeek 的配置与连接验证，不包含法规问答、摘要生成、录音转写或业务决策。无登录页面，默认本机环回访问。

验收重点：主题与布局、配置保存和错误提示、密钥不回传、数据库连接失败可见、环境重启生效、演示状态明确、macOS/Linux 启动。

## 第二阶段：人员档案与法规知识库

计划实现人员事实档案、证件与停留记录、资料导入，以及本地法规文件解析、条款结构化、版本与时效管理、精确检索与中文混合检索。

知识问答需在此阶段另行实现：检索原文、引用条款与版本、证据不足提示、AI 网关。原始法规保存在本地；法规更新通过人工导入并审核的更新包完成，不依赖运行时外部法规接口。

验收前需要确认法规材料范围、数据字段、资料来源和可用于模型处理的数据。不得将导入资料里的指令视为系统指令。

## 第三阶段：期限预警与文书模板

计划实现确定性日期规则、定时扫描、预警列表、处理记录及模板填充。应区分签证入境有效期、每次准许停留期限、实际入境记录、延期/受理回执和离境状态；资料不足时显示待核实。

限期出境相关文书的正式名称、固定措辞、文号、救济告知和版式，等待业务方提供经确认的现行模板。AI辅助填充不取代人工审查与作出决定。此阶段完成后才能讨论正式文书输出。

## 第四阶段：中文录音与智能笔录

计划实现录音采集和本地保存、中文转写、音频与转写位置关联、人工修订、摘要、关键要素抽取、模板匹配与导出。

原始音频、逐字转写、修订稿和AI摘要分别保存。说话人区分、时间戳、长音频处理和移动端录音，需要结合所选模型与真机能力验证，不能从普通聊天接口推断为已支持。

## 第五阶段：事实画像、统计与完整交付

计划实现带来源与确认状态的人员事实汇总、业务时间线、统计报表、旧数据迁移、备份恢复及运维交付。关系展示依据已核实业务事实，不自动推断违法倾向。

真正业务上线前还需要身份认证/权限、审计、HTTPS入口、数据保留策略和实际业务验收。具体实现随本阶段需求确认，不把“无登录的本机预览”当作已具备多人生产部署能力。

以上为工作范围与顺序，不代表后续模块已经开发，也不承诺未经测量的准确率、性能或交付日期。
