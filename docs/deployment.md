# macOS / Linux 运行与部署说明

## 当前运行方式

0.2.0（第二阶段）采用本机验收方式：前端监听 `127.0.0.1:5173`，后端监听 `127.0.0.1:8000`。支持 macOS 和 Linux，不提供 Windows 启动脚本。当前没有登录、身份认证和权限体系。

从仓库根目录运行：

```bash
bash scripts/setup.sh
bash scripts/dev.sh
```

`setup.sh` 使用 `backend/.venv`，不修改系统 Python 包。Node.js 需符合 `^20.19.0 || >=22.12.0`，Python 需为 3.11 或更高版本。首次安装通过 npm/pip 获取依赖，不自动安装 Node.js、Python、PostgreSQL 或本地模型。从第一阶段升级时重新执行 `setup.sh`，随后完整重启服务。

需要分别启动时，在两个终端的仓库根目录运行：

```bash
# 终端一：API
backend/.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

```bash
# 终端二：前端
npm run dev -- --port 5173 --strictPort
```

前端 `/api` 代理使用后端 8000 端口，并保留同源请求信息。`/api/health` 显示版本、阶段、当前生效环境与待重启状态。设置保存成功不表示运行环境已经切换。

当前按单个后端进程运行。不要在未验证并发配置和文件更新协调前增加多个 Uvicorn worker。

## 数据库与第二阶段升级

测试模式使用 `backend/data/test.sqlite3`，正式模式使用配置的 PostgreSQL。所有业务请求使用启动时确定的数据库连接；配置变更只有在完整重启后启用。

第二阶段启动会创建尚不存在的人员、停留记录、知识文档、条款分段及审计表，保留已有设置和数据。当前使用 SQLAlchemy `create_all` 新增表，**没有引入通用数据库结构迁移工具**；后续修改已有表结构需要单独制定迁移过程。不要通过删除数据库来完成升级。

准备 PostgreSQL 时，先创建数据库及应用账号，再在系统设置中填写主机、端口、数据库名、用户名和密码。连接测试只执行 `SELECT 1`，不建表；保存正式模式时也会验证连接。应用正式启动需要创建本应用表和后续读写的权限。

**PostgreSQL 模式尚未经过真实 PostgreSQL 服务的集成验证。** 测试中使用替身验证环境切换、失败行为和隔离逻辑，不代表已完成生产数据库验收。当前没有数据库集群、高可用、主从复制和自动备份服务。

SQLite 与 PostgreSQL 数据保持独立；切换不迁移、不合并、不复制业务数据。两个模式下的工作台均读取当前数据库，不自动注入演示人员或虚构预警。

正式配置下数据库不可用时，启动失败并输出错误，不静默改用 SQLite。优先恢复数据库连通性；确需回退时，停止服务并备份 `settings.json` 后，由维护人员把保存的环境模式改为 `test`，保留文件权限并重新启动。不要删除数据目录来解决连接故障。

## 数据目录与备份

默认数据目录为 `backend/data/`。如需更换，在启动前设置：

```bash
export NEXT_NIA_DATA_DIR="/absolute/path/to/next-nia-data"
bash scripts/dev.sh
```

后端和脚本不自动读取 `.env`。环境变量不会覆盖已保存的 API 密钥和 PostgreSQL 连接配置；更换数据目录会选择另一套配置与测试数据库。

`settings.json` 包含明文 API Key 和数据库密码，权限为 `0600`；文件权限限制不是加密。知识库原件以二进制内容保存在当前数据库，条款、元信息、人员、停留记录和审计也在同一数据库中，未单独写到上传目录。

测试环境应停止服务后备份整个数据目录，避免复制正在写入的 SQLite 文件。PostgreSQL 应使用数据库备份工具备份业务库，并另行备份 `settings.json`；仅复制项目文件不能备份 PostgreSQL 中的人员或法规原件。备份含个人资料和密钥，应按运行数据管理。

当前未提供自动备份、恢复向导和恢复演练结果。

## 默认检索与可选本地模型

默认安装仅使用本地 BM25 和字词精确匹配，不安装 SentenceTransformer 或下载模型。该方式支持离线法规检索，界面会显示实际检索模式。

可选本地语义检索要求提前准备兼容的完整 SentenceTransformer 模型目录，并在适配目标操作系统和 CPU/GPU 的环境安装：

```bash
backend/.venv/bin/python -m pip install -r backend/requirements-semantic.txt
export NEXT_NIA_EMBEDDING_MODEL_DIR="/absolute/path/to/local-embedding-model"
bash scripts/dev.sh
```

本阶段没有默认安装这些重型依赖或模型，也没有完成真实本地模型的运行、性能或质量验收。以上是可选配置路径，不代表任何具体模型已经适配。模型权重应放在项目代码仓库之外。

加载时限制为本地文件并关闭远程自定义代码，不自动联网下载。目录无效、依赖缺失、加载或推理失败时，接口会说明实际状态并使用本地词法检索。改变模型路径后重启后端；不要把“已填写路径”当作模型已经加载。

当前语义向量按请求计算，没有持久化向量数据库或大规模索引建设。大批量资料的容量、并发和响应时间需要后续实测。

## 文件解析边界

默认解析 TXT、Markdown、DOCX 正文与可提取文字的 PDF，单文件不超过 10 MiB。原件、解析文本和条款关联留在本地数据库。加密、损坏、无可提取文字或超过解析限制的文件会返回错误。

扫描 PDF 需要先通过另行部署的本地 OCR 工具转换，当前不包含 OCR 引擎。不要接入未批准的在线转换服务来代替本地处理。转换后的条款、页码和表格仍需人工核对。

## AI 网络出口与确认

连接测试访问选定服务商的固定模型列表接口。法规问答只有在 AI 与默认服务商启用、凭据已配置、检索到已发布且有效并获准外发的资料、用户明确确认本次外发后，才调用固定聊天接口。

- 硅基流动：`https://api.siliconflow.cn/v1`。
- DeepSeek：`https://api.deepseek.com`。

应用不跟随服务商 HTTP 重定向，也不自动使用进程的环境代理设置。需要受控网关出口时，应由部署网络保障这些固定目标的可达性；不要把服务商地址改成任意第三方 URL。

问答发送本次问题及获准外发的法规片段，不自动加入人员档案、停留记录或数据库配置。`allow_external` 是人工设置的许可标记，不是自动公开性或隐私检测。问题文本也会发送，请勿输入非公开个人资料。无云端出口时，保留本地检索和资料管理，AI 问答不可用。

没有真实凭据时不执行在线验证；当前尚未验证真实服务商问答、账单用量或模型效果。引用标识校验不能证明法律结论正确。

## 内网、离线与移动部署

本地业务与默认检索不需要外部字体、CDN、地图、统计、OCR 或业务数据接口。离线准备环境需收集与目标系统、CPU 架构和 Python 版本匹配的 npm 构建材料、Python wheel、PostgreSQL 安装包，以及自行选择的可选模型文件。不要把 macOS 虚拟环境直接复制到 Linux。

`setup.sh` 仍按常规软件源安装，**尚未提供或验收完整离线发行包**。

后续生产静态部署需先 `npm run build`，由本地 Web 服务器托管 `dist/`，并将同源 `/api/` 转发到 FastAPI。Vite 开发服务器和 preview 不作为正式业务服务。当前不附带未经集成验证的全栈 Compose、反向代理或系统服务配置。

环回地址不能由另一台手机访问；目前移动适配指浏览器响应式界面，目标手机尚未真机验收。实际访问需配置受控网络、HTTPS 信任、访问控制和设备测试。录音模块及其安全上下文、麦克风权限、APK/HarmonyOS 封装均未启动。
